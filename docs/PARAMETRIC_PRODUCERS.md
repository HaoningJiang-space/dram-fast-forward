# 有界多生产者条件调度编译

本轮的问题是：不读取参考执行的命令顺序，能否从多个DMA程序和冻结控制器语义中，
推导不同入口参数下的PRE/ACT/RD顺序？实现名称为**有界、路径敏感的符号调度特化**。
它不是上一轮FIFO READ规则的扩展，也尚不是对任意长度循环成立的通用调度编译器。

## 输入与边界

- 真实Up/Gate的2–4个权重DMA producer，逻辑范围取自模拟前的tile描述。
- 使用原native的CRC endpoint映射和local-address变换，再解码八个Bank和Row。
  `tools/check_producer_mapping.py`直接编译原源码函数，与Python前端核对。
- 原始架构的Bank端口原本独立；本轮将同一endpoint下的真实Bank/Row地址放入既有
  八Bank共享总线fixture。**地址映射真实，竞争拓扑是显式实验条件**，不能称为原加速器实测。
- 到达参数是符号整数。双producer一个独立偏移；三producer两个独立偏移；四producer
  使用同一个偏移的0/1/2/3倍。这些是受控到达合同，不是从真实完成日志取得的时刻。
- 长度4/8/12/16、closed/hit/conflict是有限结构变体；编译产物统一包含它们，但没有对
  任意符号长度N作归纳证明。总请求不超过64，因而没有队列满导致的接纳失败。
- 初始Row是所有旧时序义务已过期的quiescent状态。未知callback反馈、写队列及跨刷新
  区间不编译，整个不支持的调用进入原始精确控制器。

CRC含位运算。本轮枚举有界请求的物理地址，不将CRC整体宣称为仿射映射。
研究对象是映射之后的竞争条件，不以这个地址前端作为新颖性。

## 算法

状态包含：每Bank打开的Row、active/read队列、尚未到达的请求、各资源的ready时间和
时序历史。时间用整数仿射表达式表示；参数域用Presburger集合表示。

1. 从完整参数域和入口状态开始符号执行冻结策略。
2. 每次比较到达、ready或FCFS年龄时，用isl判断分支是否必真/必假。
3. 两边均可达时，拆成互补条件域，各自继续推导，不调用Ramulator寻找参考顺序。
4. 每个叶子输出入口guard、请求身份/命令序列、仿射发射时间。
5. 达到区域预算后，记录未覆盖的参数域；生成程序不能匹配它们时精确回退。

当前实现从入口重放每条符号路径，没有合并等价状态或共享符号后缀。因此区域数量和
重复分析成本都是本轮的验收对象，不能把它们藏在“编译一次”后面。

控制语义包括：active队列先于普通READ；同队列ready优先、再按年龄稳定选择；PRE
若关闭active请求所在Bank则取消本拍发射，而不是偷偷改选另一个请求。时序转移读取
同一静态模型，包含共享RD间隔、ACT间隔及四ACT历史窗口。

运行时先验证producer合同，选一次条件区域并求值时间表达式。后续按已选身份执行，
不重新调用FR-FCFS或计算prerequisite；队列中的身份查找仍有成本。原Ramulator执行
真实命令状态更新、计数和callback，因此这还不是把全部状态转移聚合成闭式F的实现。

## 正确性论证范围

若符号状态与具体入口一致，每个分裂是条件与其整数补集；isl只丢弃不可达分支。
在路径内，比较结果固定，状态转换和下一命令与翻译后的策略一致，因而可沿有限展开
步数归纳。时间表达式也来自这些转换，而非参考时间拟合。

这个论证仍依赖人工翻译的控制器语义与真实C++一致。实际验收必须与冻结Ramulator
比较全部事件、callback、最终状态以及编译区退出时的完整状态。独立共享总线checker
另查命令串行、数据总线与ACT窗口。单元测试对小例核对guard不交、覆盖及预算回退。

有限展开归纳不是参数化循环不变量。不同N目前分别分析；跨多个任意迭代的状态等价、
区域组合与自动跳跃仍未建立。

## 成本与公平比较

三种对照使用同一构建、地址、到达与入口Row：原reference、hybrid、上一轮动态资源分类。
所有请求和callback保留，编译区不减少物理工作。

`host_cpu_seconds`是既有主循环计时；新方案的入口验证/区域选择在主循环之前。
因此**不能单凭循环CPU声称端到端加速**。主结果使用包含该成本的整进程CPU，另报告
符号编译和完整C++编译/链接成本。小窗口启动开销及噪声限制结论，不将其外推到完整FFN。

判据：

| 问题 | 通过所需证据 |
|---|---|
| 超过资源分类的能力 | 自动生成含PRE/ACT/RD、随到达/Row变化的不同路径，运行时不逐请求选路 |
| 参数化与扩展性 | 区域数量、编译耗时可控；不能为每个参数点各存一份轨迹 |
| 实际收益 | 含入口成本超过hybrid；多个真实完整窗口的20%目标仍是后续门槛 |

即使第一项通过，后两项不过，也不能宣称多面体算法价值和论文贡献已经建立。

## 与已有工作的关系

[Compile-Time Event Batching](https://arxiv.org/abs/1805.04303)已经研究事件组合代码及运行时
选择；[LightningSimV2](https://arxiv.org/abs/2404.09471)区分编译图与图求值。
本轮不能把“生成代码”本身作为新颖性。

[DRAMPyML](https://arxiv.org/abs/2602.10654)用Timed Petri Nets描述和执行DRAM协议。
协议合法性不自动确定本项目FR-FCFS选择，但说明形式化DRAM语义已有直接先例。
这里新增的实验对象是竞争分支条件，而不是宣称首次形式化DRAM。

## 入口

`producer_ir.py`提取真实映射后的producer；`parametric.py`编译条件区域；
`parametric_adapter.hh`连接原控制器；`parametric_study.py`差分和计时。
`tools/measure_build.py`记录完整构建成本。大日志留在Orion研究目录，Git只保存小型
结果、生成产物、哈希与复现合同。
